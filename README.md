# Pot Log

Offline-first pottery log: install to the home screen, log a pot (photo optional, any stage), move it along its stages with a swipe, and walk the shelf with the newest pots first.

- Svelte single-page app built by Vite (`npm run build` → `dist/`).
- Pots live on the phone in IndexedDB through Dexie's free core; the shrunk photo is stored as a Blob in the same row, so a pot and its photo are saved as one unit.
- Stages are rows in the Dexie `stages` table (`src/lib/stages.js`): ten path stages (including In bisque kiln and In final firing), a waiting-on-staff state and five end states. Each pot carries its current stage and a dated `history` list; every entry stores `occurredAt` (when it happened, editable) apart from `enteredAt` (when it was typed in). Dexie version 2 adds the table and upgrades saved pots in place; version 3 adds the two kiln stage rows and `archivedAt` to each pot without changing any pot's stage (`src/lib/db.js`). Record logic is pure and tested (`src/lib/pots.js`).
- The list is photo-led and ordered newest first by the date the pot was added. Pots that have ended can be moved to an archive (a separate `archivedAt` date; the end state, photos and history are kept), which is hidden from the main list and stage chips and opened by the Archive chip. Swipe a card (pointer events, wide threshold, `src/lib/swipe.js`) to move it on; long press to select several and send them to waiting on staff or into the kiln, or archive them when every selected pot has ended.
- Glazes: the potter keeps a personal glaze shelf (Dexie version 4 `glazes` table, `id` and `name`, starting empty; `src/lib/glazes.js`). A pot stores its layers as `glazeLayers: [{ glazeId, coverage, method }]` in the order they went on (first coat first, so "A over B" is stored as B, A; the editor and every caption read top coat first), so renaming a shelf glaze renames it on every pot, and a glaze still used by a pot cannot be removed. The layer picker lists the shelf as large chips with an "Add a glaze" field inside it; layer cards are reordered by dragging a handle (pointer events, `src/lib/reorder.js`) or with the arrow buttons.
- Prompts: after Glazed a skippable "Add glazes" button appears on the undo bar; at Finished or Finished, with a flaw the glaze sheet opens at once, joined to the camera, and can be skipped. The pot screen can fill both later, and Add a pot offers both for pots recorded as finished.
- Finished photo: a separate `finishedPhoto` Blob in the pot's row (with `finishedFrom`: `camera`, `initial` or a history entry id), set by the camera or picked from the pot's own photos. Glaze layers and the photo choice are saved in one Dexie transaction (`finishPot`), which refuses a pot that is not finished, a photo that is not the pot's, an empty photo and a glaze that is not on the shelf.
- Finished pots (`src/components/FinishedPots.svelte`): a two-column photo grid of Finished and Finished-with-a-flaw pots with glaze captions, pots missing a photo or glaze first (clay placeholder and a red flag); tapping a glaze name filters to pots with it in any layer.
- Photos are shrunk in horizontal strips (`src/lib/bands.js`, `src/lib/shrink.js`) so 48 MP photos stay under iOS canvas limits.
- Workbox (via `vite-plugin-pwa`) generates the service worker and precache list; `navigator.storage.persist()` is requested after a save.
- `server/server.js` serves `dist/` on `PORT` (default 8080) and logs one JSON line per request.
- A copy of every pot on the server (`src/lib/sync.js`, `src/lib/wire.js`, `server/`): potters do nothing. Dexie version 6 gives each saved pot a random `uuid` and an `updatedAt`, and every write helper in `db.js` refreshes `updatedAt` (older installs keep their pots). On first launch the app makes a 128-bit secret, keeps it in IndexedDB (table `meta`) and sends it as a bearer token; the server keeps only its SHA-256. On first open in a browser the server also sets a `potlog_key` cookie, which the installed app moves into IndexedDB once, otherwise it makes its own. Saves stay on the phone first; the app copies on launch, on the `online` event and after each save (pull, then push): a pot goes up as one request holding the record and its photos, the later `updatedAt` replaces the earlier, and the header shows the age of the last completed copy with a nudge when it is old.
- The server (`node:http` + `node:sqlite`) keeps one SQLite file at `DATABASE_PATH` with the photos as files beside it (`photos/<potter>/<sha256>`); photos are written first, then the record row is committed in one transaction, and every query is scoped to the potter. Daily volume backups are the platform's.
- Maintainer: `node server/issue-secret.js new` makes a potter and a link (`/#key=...`) for a friend; `replace <potter id>` gives an existing copy a new secret and stops the old one; `list` shows potters. **Move to a new phone** on the old phone shows a QR of the same link. `npm run seed` fills a demo (`/#key=00112233445566778899aabbccddeeff`).

- Full export (`src/lib/exportData.js`, `src/components/ExportSheet.svelte`): **Export all pots** on the pot list builds one self-contained `.html` page from a single read transaction over pots, glazes and stages (`readExportSnapshot` in `src/lib/db.js`). The page opens with a manifest (export date, app version, counts of pots, archived pots, photos, glaze layers), then finished pots with a photo beside each "A over B" glaze line, then a journal of every pot (failed and archived pots are marked and kept). The same records are in a `<script type="application/json" id="pot-log-data">` block (glaze layers in stored order, top coat last; photos named by the `id` of their `<img>`); page and JSON are written from one record set. The file is a Blob built from parts: each photo is read in small slices, base64-encoded and dropped before the next, so no photo-sized string and no one giant string exists. A missing or empty photo stops the export with a message instead of leaving it out. The ready screen repeats the counts and has a large Save button (download link from a fresh tap) with a share-sheet button and an open-in-new-tab link as the iPhone fallback.

- The potter's own stages: **My stages** opens one ordered list with large earlier/later buttons; tapping a name opens a full-screen sheet (name, kind, photo offer, role tag, hide) and each row has "Add after" with firing suggestions (raku, soda, wood, pit, off-studio). Stages are never deleted: hiding keeps the row so pots sitting there keep their label, and can move them on. Pots refer to stages only by id, so renames, reorders and hides keep every pot's history. Dexie version 4 adds `edited`, `hidden` and `role` to stage rows and rewrites only unedited rows. Gentle, dismissible order notes (drying before the first firing, glazing before a later firing) read the role tags and show after an edit, with a move that skips a step, and on the pot (`src/lib/stageEdit.js`, `src/components/StageList.svelte`, `StageSheet.svelte`).

Run `python3 scripts/make-icons.py` to regenerate the icons. Tests: `npm test`.
